# 문맥 교정기 — 버튼별 프롬프트 정리 (검토용)

> 출처: `src/editorService.js` (2026-06-01 기준). 언어모델 검토용으로 **실제 전송되는 프롬프트를 그대로** 옮긴 문서입니다.
> 라벨(`【서술 NN】`/`【대사 NN】`/`【KPC 01】`)은 프롬프트가 아니라 앱이 응답 이후 **로컬 후처리**로 붙입니다. 따라서 아래 프롬프트에는 라벨 지시가 없습니다.

---

## 0. 전체 구조

문맥 교정기 버튼은 두 종류의 API 호출로 나뉩니다.

| 버튼 그룹 | 버튼 | 모드 키 | 호출 함수 | 대사 처리 | 입력 형태 |
|---|---|---|---|---|---|
| **전체 정리** | 원문 유지 정리 | `preserve` | `cleanText` | 대사 **포함** 전체 손질 | 원문 전체(문자열) |
| | 자연 서술 정리 | `natural` | `cleanText` | 대사 **포함** 전체 손질 | 원문 전체(문자열) |
| | 화자 개입 제거 | `remove_narrator` | `cleanText` | 대사 포함(메타 발화 제거 목적) | 원문 전체(문자열) |
| **대사는 그대로, 서술만** | 서술 보존 | `preserve` | `cleanNarrationBlocks` | 대사 **원문 보존**(API 미전송) | 서술 블록 JSON 배열 |
| | 서술 자연스럽게 | `natural` | `cleanNarrationBlocks` | 대사 **원문 보존**(API 미전송) | 서술 블록 JSON 배열 |

- **프롬프트는 제공사별로 분리**됩니다. OpenAI는 상세본, Gemini는 무료 버전을 상정한 간결본입니다.
- **모드별 temperature**: `preserve` 0.1 / `natural` 0.28 / `remove_narrator` 0.18.
- **출력 토큰 한도**: 전체 정리 `8192`. 서술만 경로는 `min(max(8192, 1600 × 블록수), 16000)`.

### 프롬프트 조립 순서

- **전체 정리(`cleanText`)**
  `최종 instructions = [모드 지시문] + [지칭 치환 블록]`
  - OpenAI: `instructions`와 `input`(`원문:\n{원문}`)을 분리 전송(Responses API).
  - Gemini: `prompt = instructions + "\n\n원문:\n" + 원문` 한 덩어리로 전송.
- **서술만(`cleanNarrationBlocks`)**
  `최종 instructions = [모드 지시문] + [지칭 치환 블록] + [JSON 블록 작업 규칙]`
  - `input` = 서술 블록들의 JSON 문자열 배열(대사 블록은 포함하지 않음).
  - Gemini는 추가로 `responseMimeType: application/json` + `blocks` 스키마를 함께 전송(거부 시 스키마 없이 1회 재시도).

### 지칭 치환 블록의 동적 값

모든 모드 지시문 뒤에 붙는 "지칭 치환" 블록은 사용자 설정값으로 채워집니다.

- `변환 대상`(targetTerms): 기본 `"탐사자님", "탐사자", "PC", "플레이어"` (사용자가 KPC 등 추가/수정 가능)
- `변환 결과`(targetName): 기본 `"당신"`
- `applyTargetToDialogue`(대사 안 지칭도 변경): 기본 꺼짐
- `allowOmitRepeatedTarget`(반복 지칭 생략 허용): 기본 켜짐

아래 본문에서는 **기본값 기준**으로 조건부 문장을 표기하고, 토글에 따라 달라지는 문장은 주석으로 표시합니다.

# A. OpenAI 프롬프트 (상세본)

## A-0. 공통 원칙 (모든 모드 앞에 공통으로 들어감)

```
당신은 TRPG 시나리오 문장을 정리하는 편집 보조자입니다.

공통 원칙:
- 원문의 사건, 정보, 분위기, 핵심 어휘를 유지합니다.
- 새로운 설정, 감정, 해석, 비유, 배경 묘사를 추가하지 않습니다.
- 원문에 없는 고유명사나 새로운 묘사를 만들지 않습니다.
- 문장을 더 화려하게 만들려고 하지 않습니다.
- AI가 자주 덧붙이는 장식적 미사여구, 교훈적 문장, 과장된 감탄, 원문에 없는 분위기어를 넣지 않습니다.
- 결과문만 출력합니다.
- 설명, 주석, 변경 이유, 제목은 출력하지 않습니다.
- 코코포리아 채팅창에 붙여넣기 좋게 줄바꿈을 정리합니다.
```

## A-1. 원문 유지 정리 (`preserve`) — temperature 0.1

```
작업: 원문 보존 정리 / 보수형
목표:
- 원문을 새로 쓰지 말고, 읽기 불편한 어미와 화자체만 최소한으로 정리합니다.
- 원문의 문장 순서, 정보량, 핵심 표현, 명사 선택을 가능한 한 유지합니다.
- 문장을 압축하거나 의미를 요약하지 않습니다.
- 원문의 시제와 어미가 크게 문제되지 않으면 유지합니다. 원문이 ~합니다체이면 보존형에서는 ~합니다체를 유지할 수 있습니다.

허용:
- 어색한 대화체 어미를 GM 평서문으로 바꿉니다.
- 직접 호명, 메타 지칭, 과한 말 걸기 표현을 중립 서술로 정리합니다.
- 조사, 어순, 줄바꿈은 읽기 좋게 조정할 수 있습니다.
- 플레이어/탐사자의 행동이 분명한 문장인데 주어가 빠져 어색하면, 첫 문장에만 필요한 주어를 보완할 수 있습니다.

제한:
- 원문에 있는 주어, 목적어, 장소, 상태를 임의로 생략하지 않습니다.
- 단문을 지나치게 압축하지 않습니다.
- 원문에 없는 감각 묘사, 분위기어, 심리 해석을 넣지 않습니다.
- 자연스럽게 만들기 위해 내용을 재구성하는 일은 최소화합니다.
- 원문의 수식어를 강화하지 않습니다. 예: "다소 떨어진"을 "다소 멀리 떨어진"처럼 키우지 않습니다.
- 한 문단 안에서 같은 호칭이 반복되어도, 의미가 흐려질 정도로 생략하지 않습니다.

출력 형식:
- 원문 문단 구조를 대체로 유지하되, 코코포리아에서 읽기 쉽도록 긴 서술은 단락으로 나눕니다.
- 한 서술 블록 안에 3문장 이상이 있으면 의미 단위마다 빈 줄을 넣습니다.
- 한 문장을 과하게 길게 합치지 않습니다.
- 줄바꿈은 문체 변경이 아니라 가독성 조정으로 간주합니다.

예시:
원문: 경찰의 눈을 피해 음지에서 기어 다니는 죄 많은 그들…… 아, 물론 동정하는 건 아니에요. 정의로운 신입 형사인 당신에게 죄는 뿌리 뽑아야 할 악덕이며, 악당은 혼쭐을 내줘야 할 불량 씨앗이니까요.
결과: 경찰의 눈을 피해 음지에서 기어 다니는 죄 많은 자들.

물론, 동정할 필요는 없다.
정의로운 신입 형사에게 죄는 뿌리 뽑아야 할 악덕이고,
악당은 혼쭐을 내줘야 할 불량한 씨앗이다.
```

## A-2. 자연 서술 정리 (`natural`) — temperature 0.28

```
작업: 자연 서술 정리 / 자연형
목표:
- 원문의 사건, 정보, 장면 순서, 핵심 어휘를 유지하면서 GM이 읽기 자연스러운 서술로 정리합니다.
- 문맥이 끊기거나 기계적으로 나열된 문장을 자연스럽게 잇습니다.
- 원문 보존보다 낭독감, 문단 호흡, 자연스러운 연결을 조금 더 우선합니다.
- 자연형은 코코포리아에서 GM이 바로 읽는 평서문입니다. 결과는 기본적으로 "~다", "~했다", "~한다" 체로 정리하고, 원문이 ~합니다체여도 필요한 경우 평서형으로 바꿉니다.

허용:
- 문장 구조 변경, 어순 조정, 문장 분리와 결합을 허용합니다.
- 같은 의미를 더 자연스러운 문장으로 바꿀 수 있습니다.
- 필요한 경우 "아무래도", "모양이다", "듯하다", "원한다면" 같은 완충 표현을 사용할 수 있습니다.
- 같은 호칭이 가까운 문장에 반복되면 문맥상 자연스럽게 일부를 생략할 수 있습니다.
- 같은 호칭이 가까운 문장에 반복되면 일부를 생략하거나 "함께 배치된 사람", "그", "상대", 해당 인물명처럼 문맥상 자연스러운 표현으로 바꿀 수 있습니다.
- 장면 beat가 바뀌면 빈 줄을 넣어 1~3문장 단위로 나눕니다.
- 한 서술 블록 안에 3문장 이상이 있으면 반드시 빈 줄을 넣어 문단을 나눕니다.

제한:
- 원문에 없는 사건, 감정, 비유, 배경 묘사는 추가하지 않습니다.
- 원문보다 과하게 문학적이거나 극적인 문장으로 바꾸지 않습니다.
- "침묵", "어둠", "기묘한", "섬뜩한" 같은 분위기어를 원문에 없는데 임의로 추가하지 않습니다.
- NPC의 의도나 감정을 단정하지 말고, 원문이 추정형이면 추정형을 유지합니다.

출력 형식:
- 코코포리아에서 읽기 좋게 의미 단위마다 빈 줄을 넣습니다.
- 한 문단은 보통 1~3문장으로 유지합니다.
- 긴 설명은 여러 문단으로 나눕니다.

예시:
원문: 신입 경찰이 당신에게 자꾸만 말을 걸어옵니다. 아무래도 탐사자 또한 신입이다보니까, 그런 기류를 감지하고 친해지고 싶어 하는 걸까요? 탐사자가 원한다면 신입에게 정보를 흘려줄 수 있습니다.
결과: 신입 경찰이 당신에게 자꾸 말을 걸어온다.

아무래도 당신 또한 신입이다 보니,
그런 기류를 감지하고 친해지고 싶어 하는 모양이다.

원한다면, 신입 경찰에게 정보를 흘려줄 수 있다.

예시:
원문: 전시장의 구석 벽에 섭니다. 아리아드네와는 다소 떨어진 곳이라 이 구역 경계는 한산합니다. 탐사자 외에 배치된 이는 갓 신입처럼 보이는, 경찰 정복을 서투르게 입은 사람입니다. 모자가 삐뚤어진 듯 쩔쩔매고 있습니다.
결과: 당신은 전시장의 구석 벽에 섰다.

아리아드네와는 다소 떨어진 곳이라, 이 구역 경계는 한산하다.
함께 배치된 사람은 갓 신입처럼 보였고, 경찰 정복도 서투르게 걸친 상태였다.

그는 모자가 삐뚤어진 것도 모른 채 쩔쩔매고 있다.
```

## A-3. 화자 개입 제거 (`remove_narrator`) — temperature 0.18

```
작업: 화자 개입 제거 / GM 지문화
목표:
- 시나리오 작성자가 독자, 플레이어, 탐사자에게 직접 말을 거는 흔적을 제거합니다.
- 질문형, 감탄형, 농담형 메타 발화를 GM이 바로 읽을 수 있는 지문형 서술로 바꿉니다.
- 문장을 아름답게 만들기보다, 세션 진행 중 읽기 쉬운 중립 지문으로 정리합니다.

반드시 제거 또는 변환:
- "아, 물론", "아니에요", "~일까요?", "~겠죠?", "~군요", "~해볼까요", "그렇지 않나요?" 같은 화자 개입 표현
- 독자나 플레이어에게 말을 거는 2인칭 안내문
- 작가의 농담, 감탄, 추임새, 평가가 드러나는 문장
- 불필요한 수사적 질문. 질문형 문장은 가능한 한 확정형 지문으로 바꿉니다.

허용:
- 메타 질문을 장면 판단이나 조건문으로 바꿉니다.
- "탐사자가 원한다면", "원한다면"처럼 세션 선택지를 안내하는 조건문은 유지할 수 있습니다.
- 직접 호명이 필요한 PC 행동 지문은 설정된 지칭 규칙을 사용합니다.

제한:
- 원문에 없는 사건, 감정, 비유, 배경 묘사를 추가하지 않습니다.
- NPC 대사처럼 보이는 문장은 임의로 바꾸지 않습니다.
- 원문에 있는 판단이 추정형이면 지나치게 단정하지 않습니다. 다만 "~일까요?"처럼 화자가 묻는 형식은 지문형 추정으로 바꿉니다.
- 자연형처럼 문장을 과하게 재구성하지 않습니다. 화자 개입을 걷어내는 데 필요한 범위에서만 문장 구조를 바꿉니다.

출력 형식:
- 코코포리아에서 읽기 좋게 의미 단위로 빈 줄을 넣습니다.
- 결과문만 출력합니다.

예시:
원문: 아, 물론 동정하는 건 아니에요. 정의로운 신입 형사인 당신에게 죄는 뿌리 뽑아야 할 악덕이며, 악당은 혼쭐을 내줘야 할 불량 씨앗이니까요.
결과: 정의로운 신입 형사에게 죄는 뿌리 뽑아야 할 악덕이다.
악당은 혼쭐을 내줘야 할 불량한 씨앗이다.

예시:
원문: 아무래도 탐사자 또한 신입이다보니까, 그런 기류를 감지하고 친해지고 싶어 하는 걸까요? 탐사자가 원한다면 신입에게 정보를 흘려줄 수 있습니다.
결과: 신입 경찰은 당신 또한 신입이라는 점을 의식하고 있다.
그는 그 점에서 동질감을 느끼며 가까워지려 하는 듯하다.

원한다면, 신입 경찰에게 정보를 흘려줄 수 있다.
```

## A-4. 지칭 치환 블록 (OpenAI, 위 모든 모드 뒤에 추가) — 기본값 기준

```
지칭 치환 최우선 규칙:
- 이 규칙은 preserve/natural 모드의 "원문 보존" 규칙보다 우선합니다.
- 변환 대상 지칭: "탐사자님", "탐사자", "PC", "플레이어"
- 변환 결과 지칭: "당신"
- 결과의 서술 영역에서 변환 대상 지칭이 나오면 반드시 "당신" 기준으로 정리합니다.
- 변환 대상이 PC/탐사자/플레이어/KPC 등 캐릭터 지칭일 경우, 원문에 대상 지칭이 직접 없어도 장면 지문상 해당 캐릭터의 위치, 행동, 선택을 말하는 문장은 "당신"을 주어로 삼아 정리할 수 있습니다.
- 특히 "~합니다", "~습니다", "~섭니다"처럼 시나리오가 대상 캐릭터에게 행동을 안내하는 문장은 필요하면 "당신은/는" 또는 "당신이/가"를 보완합니다.
- 첫 서술 문장에서 PC/탐사자의 행동이나 위치가 시작되면 주어를 생략하지 않습니다.
- 조사(이/가, 은/는, 을/를, 와/과, 에게, 의)는 문맥과 발음에 맞게 자연스럽게 조정합니다.
- 같은 문단에서 "당신" 지칭이 반복되어 어색하면 한 서술 블록 안에서 같은 호칭을 1회 넘게 반복하지 않는 것을 기본으로 합니다. 두 번째 이후의 반복 지칭은 문맥상 자연스럽게 생략하거나, '함께 배치된 사람', '그', '상대'처럼 자연스러운 표현으로 대체합니다. 단, 첫 지칭이나 의미가 불명확해지는 곳은 생략하지 않습니다.
- 따옴표 안 NPC 대사는 원칙적으로 수정하지 않습니다. 대사 내부의 지칭도 그대로 보존합니다.
- 변환 대상 단어가 직업명, 세계관 용어, 고유명사의 일부로 명백히 쓰인 경우에는 억지로 바꾸지 않습니다.
```

> 토글에 따라 달라지는 두 줄:
> - `반복 지칭 생략 허용`이 꺼지면 → `지칭을 생략하지 말고 필요한 곳에 유지합니다.`
> - `대사 안 지칭도 변경`이 켜지면 → `대사 안의 대상 지칭도 필요한 경우 "당신"로 정리할 수 있습니다.`

# C. 검토 시 참고 포인트 (선택)

검토하는 AI에게 함께 물어보면 좋은 항목:

1. **모드 간 변별력**: `원문 유지`(보수) vs `자연 서술`(적극) vs `화자 개입 제거`(목적 한정)의 경계가 프롬프트만 보고도 분명한가? 모델이 강도를 혼동할 여지는?
2. **전체 정리 vs 서술만의 차이**: 전체 정리는 대사까지 손질, 서술만은 대사 원문 보존 — 이 의도가 프롬프트에 충분히 드러나는가? (현재 전체 정리 경로에는 "대사를 보존하라"는 명시가 없고, 지칭 치환 블록의 "따옴표 안 NPC 대사는 원칙적으로 수정하지 않습니다"만 존재)
3. **지칭 치환의 우선순위**: "원문 보존보다 우선"이라는 규칙이 보수형(preserve)의 보존 목표와 충돌하지 않는가?
4. **Gemini 간결본**: 무료 모델에서 버튼별 특색을 유지하기에 충분한 최소 정보가 담겼는가? 더 줄이거나 보강할 지점은?
5. **출력 안정성**: 라벨/마크다운 금지, JSON 블록 개수·순서 보존 지시가 모델 실수를 충분히 막는가?

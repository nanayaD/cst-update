# 배포 전 보안·품질 최종 체크리스트

## 1. 목적

이 문서는 TRPG 번역·교정 도구를 배포하기 전에 확인해야 할 보안·품질 점검 항목을 정리한 체크리스트이다.

점검 대상은 다음 세 단계로 나눈다.

```text
1. 빌드 전 점검
2. 빌드 후 점검
3. 배포 직전 점검
```

이 체크리스트는 무설치 exe 배포와 설치형 exe 배포 모두에 적용한다.

## 2. 최우선 확인 항목

배포 직전에 최소한 다음 세 가지는 반드시 확인한다.

```text
1. 배포본 안에 개인 설정 파일, API 키, 로그 파일이 포함되어 있지 않은가
2. 오류 로그에 API 키, Authorization 헤더, 원문, 결과 전문이 남지 않는가
3. 업데이트 정보가 올바른 latest.json과 정상 다운로드 링크를 가리키는가
```

## 3. 빌드 전 점검

빌드 전에는 소스코드, 설정 파일, 프로젝트 폴더를 확인한다.

### 3.1 버전 정보

- [ ] 앱 내부 버전 번호를 올렸다.
- [ ] 버전 형식은 `major.minor.patch` 형식이다.
- [ ] 예: `0.1.0`, `0.1.1`, `0.2.0`, `1.0.0`
- [ ] 버전 비교는 문자열 비교가 아니라 semver 방식으로 처리한다.
- [ ] `0.10.0`이 `0.2.0`보다 높은 버전으로 판단되는지 확인했다.

### 3.2 API 키와 민감정보

- [ ] 소스코드 안에 개발자 API 키가 없다.
- [ ] 테스트용 API 키가 코드에 남아 있지 않다.
- [ ] `.env` 파일이 배포 대상에 포함되지 않는다.
- [ ] `config.json`, `settings.json`, `test_key.txt` 같은 개인 설정 파일이 배포 대상에 포함되지 않는다.
- [ ] API 키는 사용자가 직접 입력하도록 되어 있다.
- [ ] API 키는 실행 파일 옆이 아니라 사용자별 설정 폴더 또는 OS 보안 저장소에 저장된다.

### 3.3 설정 저장 위치

- [ ] 사용자 설정은 AppData 하위 프로그램 전용 폴더에 저장된다.
- [ ] API 키와 사용자 설정이 실행 파일 옆에 저장되지 않는다.
- [ ] 무설치판과 설치형판이 같은 설정 폴더명을 사용한다.
- [ ] 다른 PC로 exe만 복사했을 때 API 키가 따라가지 않는 구조이다.

권장 설정 위치 예시:

```text
C:\Users\사용자명\AppData\Roaming\TRPGTranslatorProofreader\
```

권장 로그 위치 예시:

```text
C:\Users\사용자명\AppData\Local\TRPGTranslatorProofreader\logs\
```

### 3.4 업데이트 기능

- [ ] 업데이트 기능은 다운로드 링크 열기까지만 구현되어 있다.
- [ ] 자동 다운로드 기능이 없다.
- [ ] 자동 설치 기능이 없다.
- [ ] 실행 중인 exe를 자동으로 교체하지 않는다.
- [ ] 백그라운드 상주 업데이트 기능이 없다.
- [ ] 업데이트 확인 실패가 프로그램 실행 실패로 이어지지 않는다.
- [ ] 업데이트 확인 URL은 HTTPS 주소이다.
- [ ] 테스트용 업데이트 URL이 실배포판에 남아 있지 않다.

### 3.5 latest.json 구조

- [ ] `latest.json`에는 민감한 정보가 없다.
- [ ] `latest.json`에는 API 키가 없다.
- [ ] `latest.json`에는 다운로드 비밀번호가 없다.
- [ ] `latest.json`에는 개인 연락처가 없다.
- [ ] `latest.json`의 `version`, `downloadUrl`, `packageType`, `required`, `notes` 필드가 정상 처리된다.
- [ ] `packageType`이 `installer`일 때 설치형 전환 안내가 표시된다.

권장 예시:

```json
{
  "version": "0.2.0",
  "releaseDate": "2026-06-01",
  "downloadUrl": "https://example.com/download",
  "packageType": "portable",
  "required": false,
  "notes": [
    "업데이트 확인 기능 추가",
    "일부 UI 오류 수정"
  ]
}
```

### 3.6 로그 처리

- [ ] 오류 로그 기능이 구현되어 있다.
- [ ] 오류 로그는 AppData Local 하위 프로그램 전용 폴더에 저장된다.
- [ ] 로그 저장 실패가 프로그램 실행 실패로 이어지지 않는다.
- [ ] API 키가 로그에 기록되지 않는다.
- [ ] Authorization 헤더가 로그에 기록되지 않는다.
- [ ] 번역 원문 전문이 로그에 기록되지 않는다.
- [ ] 교정 원문 전문이 로그에 기록되지 않는다.
- [ ] 번역 결과 전문이 로그에 기록되지 않는다.
- [ ] 교정 결과 전문이 로그에 기록되지 않는다.
- [ ] 로그 저장 전 민감정보 마스킹이 적용된다.
- [ ] 로그 파일 크기와 보관 개수 제한이 있다.

### 3.7 파일 처리

- [ ] 프로그램은 사용자가 직접 선택한 파일만 읽는다.
- [ ] 문서 폴더, 다운로드 폴더, 드라이브 전체를 자동 스캔하지 않는다.
- [ ] 출력 파일은 사용자가 지정한 위치에만 저장된다.
- [ ] 기존 파일을 덮어쓸 때 확인 절차가 있다.
- [ ] 삭제 기능은 프로그램 전용 폴더만 대상으로 한다.
- [ ] 사용자가 직접 저장한 작업물은 삭제하지 않는다.

### 3.8 외부 통신

- [ ] 프로그램이 사용하는 외부 통신 주소가 명확하다.
- [ ] 업데이트 확인은 정해진 HTTPS URL만 사용한다.
- [ ] API 요청은 사용자가 선택한 API 제공사로만 전송된다.
- [ ] 불필요한 외부 통신 주소가 없다.
- [ ] 개발자 서버로 API 키, 원문, 결과물을 전송하지 않는다.

예시:

```text
업데이트 확인:
https://example.com/latest.json

OpenAI API:
https://api.openai.com/

Gemini API:
https://generativelanguage.googleapis.com/

Claude API:
https://api.anthropic.com/
```

### 3.9 디버그 요소 제거

- [ ] 배포판에서 디버그 모드가 꺼져 있다.
- [ ] 개발자 콘솔이 자동으로 열리지 않는다.
- [ ] 테스트 버튼이 제거되어 있다.
- [ ] 테스트 API 요청 기능이 제거되어 있다.
- [ ] 테스트용 URL이 제거되어 있다.
- [ ] 샘플 API 키가 제거되어 있다.
- [ ] 과도한 콘솔 출력이 제거되어 있다.

### 3.10 외부 라이브러리

- [ ] 사용 중인 외부 라이브러리 목록을 확인했다.
- [ ] 사용하지 않는 패키지를 제거했다.
- [ ] 이름이 이상하거나 출처가 불명확한 패키지가 없다.
- [ ] 패키지 잠금 파일을 유지한다.
- [ ] Python 사용 시 `requirements.txt`를 확인했다.
- [ ] Node/Electron 사용 시 `package.json`과 `package-lock.json`을 확인했다.

## 4. 빌드 후 점검

빌드 후에는 실제 배포 산출물을 확인한다.

### 4.1 배포 파일 내용물 확인

- [ ] 배포본 안에 `.env` 파일이 없다.
- [ ] 배포본 안에 개인 `config.json`이 없다.
- [ ] 배포본 안에 개인 `settings.json`이 없다.
- [ ] 배포본 안에 로그 파일이 없다.
- [ ] 배포본 안에 테스트용 API 키 파일이 없다.
- [ ] 배포본 안에 개발 중 임시 파일이 없다.
- [ ] 배포본 안에 불필요한 테스트 데이터가 없다.
- [ ] 파일명에 버전이 명시되어 있다.

파일명 예시:

```text
TRPGTranslatorProofreader-0.2.0.exe
TRPGTranslatorProofreader-0.2.0.zip
TRPGTranslatorProofreader-1.0.0-setup.exe
```

### 4.2 최초 실행 테스트

- [ ] 새 사용자 환경처럼 실행했을 때 정상 실행된다.
- [ ] 설정 폴더가 없을 때 자동 생성된다.
- [ ] API 키 미입력 상태에서도 프로그램이 비정상 종료되지 않는다.
- [ ] API 키 입력 안내가 정상 표시된다.
- [ ] API 키 저장 위치가 실행 파일 옆이 아니다.
- [ ] 프로그램 폴더에 사용자 설정 파일이 생성되지 않는다.

### 4.3 업데이트 확인 테스트

- [ ] 원격 버전이 현재 버전보다 높으면 업데이트 알림이 표시된다.
- [ ] 원격 버전이 현재 버전과 같으면 업데이트 알림이 표시되지 않는다.
- [ ] 원격 버전이 현재 버전보다 낮으면 업데이트 알림이 표시되지 않는다.
- [ ] `0.10.0`을 `0.2.0`보다 높은 버전으로 판단한다.
- [ ] `downloadUrl` 버튼을 누르면 기본 브라우저가 열린다.
- [ ] `notes`가 여러 줄일 때 정상 표시된다.
- [ ] `packageType`이 `installer`일 때 설치형 전환 안내가 표시된다.
- [ ] `required`가 `true`일 때 일반 업데이트보다 강한 안내가 표시된다.

### 4.4 네트워크 오류 테스트

- [ ] 인터넷 연결이 없어도 프로그램이 정상 실행된다.
- [ ] `latest.json` 주소가 잘못되어도 프로그램이 정상 실행된다.
- [ ] `latest.json` 내용이 깨져 있어도 프로그램이 정상 실행된다.
- [ ] 업데이트 확인 실패가 사용자에게 과도한 오류 팝업으로 표시되지 않는다.
- [ ] 업데이트 확인 실패는 필요한 경우 로그에만 기록된다.

### 4.5 오류 로그 테스트

- [ ] 의도적으로 오류를 발생시켰을 때 `error.log`가 생성된다.
- [ ] 로그에 앱 버전, 발생 시각, 오류 타입, 오류 메시지, 스택 트레이스가 기록된다.
- [ ] 로그에 API 키가 기록되지 않는다.
- [ ] 로그에 Authorization 헤더가 기록되지 않는다.
- [ ] 로그에 번역 원문 전문이 기록되지 않는다.
- [ ] 로그에 교정 원문 전문이 기록되지 않는다.
- [ ] 로그에 번역 결과 전문이 기록되지 않는다.
- [ ] 로그에 교정 결과 전문이 기록되지 않는다.
- [ ] 로그 폴더 열기 버튼이 정상 동작한다.
- [ ] 로그 복사 기능이 있다면 민감정보 마스킹 후 복사된다.
- [ ] 로그 삭제 기능이 있다면 logs 폴더 안의 로그만 삭제한다.
- [ ] 로그 파일 크기 제한과 보관 개수 제한이 동작한다.

### 4.6 파일 입출력 테스트

- [ ] 사용자가 선택한 파일만 읽는다.
- [ ] 출력 저장 위치를 사용자가 지정할 수 있다.
- [ ] 기존 파일 덮어쓰기 전에 확인한다.
- [ ] 저장 실패 시 프로그램이 비정상 종료되지 않는다.
- [ ] 읽기 실패 시 사용자에게 적절히 안내한다.
- [ ] 프로그램이 임의로 폴더 전체를 스캔하지 않는다.

### 4.7 클립보드 테스트

- [ ] 결과 복사는 사용자가 명시적으로 버튼을 눌렀을 때만 수행된다.
- [ ] API 키가 자동으로 클립보드에 복사되지 않는다.
- [ ] 오류 로그 복사 시 API 키와 원문이 포함되지 않는다.
- [ ] 클립보드에 복사되는 내용이 사용자가 예상할 수 있는 범위이다.

### 4.8 삭제 기능 테스트

- [ ] 삭제 기능은 프로그램 전용 폴더만 대상으로 한다.
- [ ] AppData 전체를 삭제하지 않는다.
- [ ] Documents 폴더를 삭제하지 않는다.
- [ ] Downloads 폴더를 삭제하지 않는다.
- [ ] 드라이브 루트 또는 사용자 작업 폴더를 삭제하지 않는다.
- [ ] 사용자가 직접 저장한 번역 결과와 교정 결과를 삭제하지 않는다.

## 5. 설치형 배포 추가 점검

설치형 exe로 배포할 경우 다음 항목을 추가로 확인한다.

### 5.1 설치 동작

- [ ] 설치파일이 정상 실행된다.
- [ ] 설치 위치가 정상 지정된다.
- [ ] 시작 메뉴 바로가기가 생성된다.
- [ ] 바탕화면 바로가기 옵션이 정상 동작한다.
- [ ] Windows 앱 제거 목록에 표시된다.
- [ ] 기존 버전 위에 설치했을 때 설정이 유지된다.

### 5.2 언인스톨 동작

- [ ] 기본 제거 시 프로그램 파일만 삭제된다.
- [ ] 기본 제거 시 API 키와 사용자 설정은 유지된다.
- [ ] 완전 제거 옵션이 있는 경우 사용자에게 명확히 안내된다.
- [ ] 완전 제거 시에도 프로그램 전용 AppData 폴더만 삭제된다.
- [ ] 사용자가 직접 저장한 작업물은 삭제되지 않는다.

완전 제거 안내문 예시:

```text
사용자 설정도 함께 삭제하시겠습니까?

이 항목을 선택하면 저장된 API 키, 사용자 설정, 최근 사용 기록이 삭제됩니다.
나중에 다시 설치해도 기존 설정을 복구할 수 없습니다.
```

### 5.3 무설치판에서 설치형 전환

- [ ] 무설치판의 업데이트 알림이 설치형 setup.exe 링크를 연다.
- [ ] 설치형 전환 안내 문구가 표시된다.
- [ ] 설치형 설치 후 기존 AppData 설정을 그대로 읽는다.
- [ ] 설치 완료 후 기존 무설치 exe는 사용자가 직접 삭제하도록 안내한다.

안내문 예시:

```text
새 설치형 버전이 있습니다.

이번 버전부터 설치형 프로그램으로 배포됩니다.
기존 무설치 exe를 삭제하기 전에 새 설치형 버전을 먼저 설치해 주세요.

API 키와 사용자 설정은 유지됩니다.
설치 완료 후 기존 무설치 exe는 삭제해도 됩니다.
```

## 6. 배포 직전 점검

실제 다운로드 링크를 배포하기 직전에 확인한다.

### 6.1 latest.json 최종 확인

- [ ] `version` 값이 배포 파일 버전과 일치한다.
- [ ] `releaseDate`가 올바르다.
- [ ] `downloadUrl`이 실제 배포 파일 링크를 가리킨다.
- [ ] `packageType` 값이 배포 형태와 일치한다.
- [ ] `required` 값이 의도한 상태이다.
- [ ] `notes`에 변경점이 정확히 적혀 있다.
- [ ] `latest.json`에 비밀번호나 API 키가 없다.
- [ ] `latest.json`은 HTTPS 주소에서 제공된다.

### 6.2 배포 링크 확인

- [ ] 다운로드 링크가 정상적으로 열린다.
- [ ] 다운로드 파일명이 올바르다.
- [ ] 다운로드 파일 버전이 latest.json의 버전과 일치한다.
- [ ] 비밀번호 공유가 필요한 경우 비밀번호는 latest.json에 넣지 않았다.
- [ ] 링크와 비밀번호는 같은 공개 문서에 함께 적지 않는다.
- [ ] 가능하면 파일 해시값을 기록했다.

SHA256 기록 예시:

```text
파일명: TRPGTranslatorProofreader-0.2.0.exe
SHA256: <해시값>
```

### 6.3 배포 안내문 확인

- [ ] API 키는 각 사용자가 직접 발급해야 한다는 안내가 있다.
- [ ] 사용하던 프로그램 폴더를 재압축해 공유하지 말라는 안내가 있다.
- [ ] 입력 텍스트가 선택한 API 제공사로 전송될 수 있다는 안내가 있다.
- [ ] 개발자가 API 키, 원문, 결과물을 수집하지 않는다는 안내가 있다.
- [ ] 오류 문의 시 로그 파일을 직접 확인한 뒤 전달하라는 안내가 있다.

권장 안내문:

```text
이 프로그램은 사용자가 직접 입력한 API 키를 통해 번역 및 교정 요청을 보냅니다.
개발자는 사용자의 API 키를 제공하거나 수집하지 않습니다.

입력한 텍스트는 사용자가 선택한 API 제공사로 전송될 수 있습니다.
전송 범위와 보관 정책은 각 API 제공사의 약관과 설정을 따릅니다.

API 키, 입력 원문, 번역 결과는 개발자 서버로 전송되지 않습니다.
업데이트 확인 시에는 최신 버전 정보 파일만 확인합니다.

본인이 사용하던 프로그램 폴더를 재압축하여 공유하지 마십시오.
설정 파일에 API 키 또는 개인 설정이 포함될 수 있습니다.
```

## 7. 배포 후 확인

배포 후에는 실제 사용자 환경에서 최소 1회 확인한다.

- [ ] 본인 PC에서 새 버전 다운로드 링크가 정상 작동한다.
- [ ] 지인 1명 이상의 PC에서 실행 및 업데이트 확인이 정상 작동한다.
- [ ] API 키 미입력 상태에서 오류 없이 안내가 표시된다.
- [ ] 오류 발생 시 로그가 정상 생성된다.
- [ ] 사용자가 기존 설정을 유지한 채 새 버전을 사용할 수 있다.

## 8. 배포 중단 기준

다음 문제가 발견되면 배포를 중단하고 수정 후 다시 빌드한다.

```text
배포본에 API 키 또는 개인 설정 파일이 포함됨
로그에 API 키 또는 원문 전문이 남음
업데이트 링크가 잘못된 파일을 가리킴
프로그램이 사용자 파일을 임의로 삭제함
네트워크 오류만으로 프로그램 실행이 불가능함
API 요청 실패 시 원문이나 키가 오류창에 노출됨
실행 파일 옆에 사용자 설정이 저장됨
설치형 제거 시 사용자 작업물이 삭제됨
```

## 9. 코딩 AI 검토 요청용 요약

코딩 AI에게 다음 항목을 기준으로 검토를 요청한다.

```text
다음 체크리스트를 기준으로 배포 전 보안·품질 검토를 수행해 주세요.

검토 범위:
1. 코드 안에 API 키, 테스트 키, 민감정보가 남아 있는지 확인
2. 사용자 API 키 저장 위치가 실행 파일 옆이 아닌지 확인
3. 오류 로그에 API 키, Authorization 헤더, 원문, 결과 전문이 남지 않는지 확인
4. 업데이트 확인 기능이 다운로드 링크 열기까지만 수행하는지 확인
5. 자동 다운로드, 자동 설치, 실행 중 exe 교체 기능이 없는지 확인
6. latest.json에 민감정보가 들어가지 않는 구조인지 확인
7. 네트워크 오류와 latest.json 오류가 앱 실행 실패로 이어지지 않는지 확인
8. 파일 읽기/쓰기/삭제가 사용자 선택 경로 또는 프로그램 전용 폴더로 제한되는지 확인
9. 배포 산출물에 .env, config, logs, 테스트 파일이 포함되지 않는지 확인
10. 무설치판과 설치형판이 같은 AppData 설정 폴더를 사용하는지 확인
11. 설치형 제거 시 프로그램 전용 폴더 외의 파일을 삭제하지 않는지 확인
12. 디버그 모드, 개발자 콘솔, 테스트 버튼, 테스트 URL이 배포판에 남아 있지 않은지 확인
```
